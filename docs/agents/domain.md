# Domain docs

## Перед дослідженням

- Прочитай кореневий `CONTEXT.md`.
- Перевір `docs/adr/` на рішення, що стосуються теми.
- Якщо файлу або релевантного ADR немає, продовжуй без зауваження про його відсутність.

## Структура

Це single-context репозиторій: є один кореневий `CONTEXT.md` і загальні ADR у `docs/adr/`. Не створюй `CONTEXT-MAP.md`, доки проєкт не стане справжнім monorepo з окремими доменними контекстами.

## Мова домену

У Issues, специфікаціях, тестах та інтерфейсах використовуй терміни з глосарія. Якщо терміну немає, спершу перевір, чи не є це синонімом наявного; реальний новий термін додавай через `domain-modeling` без технічних деталей.

Якщо робота суперечить ADR, явно назви конфлікт і не обходь рішення мовчки.

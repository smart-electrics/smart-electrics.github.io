# Repository foundation acceptance criteria

## Purpose

Цей bootstrap створює керований фундамент для майбутнього luxury-сайту Smart Electrics: статичний Jekyll-проєкт для GitHub Pages, чітку мову домену, GitHub-процес та відтворювану багаторольову агентну роботу. Він не затверджує непідтверджені маркетингові твердження.

## Acceptance criteria

### Repository and deployment

- [ ] Репозиторій містить Jekyll-конфігурацію та відтворюваний локальний спосіб зібрати сайт.
- [ ] GitHub Actions збирає Jekyll із зафіксованими залежностями та публікує результат на GitHub Pages.
- [ ] Workflow має мінімально необхідні permissions, concurrency і не виводить секрети.
- [ ] Сайт коректно працює як user/org site GitHub Pages із кореня `https://smart-electrics.github.io/`; внутрішні asset paths лишаються сумісними з `relative_url`.
- [ ] Збірка завершується успішно в чистому середовищі, а згенеровані артефакти не комітяться без потреби.

### Information architecture and luxury experience

- [ ] Домашня сторінка одразу пояснює, що Smart Electrics супроводжує електромонтаж від чорнового монтажу до розумного будинку, без вигаданих підтверджень.
- [ ] Навігація є зрозумілою з клавіатури, працює на мобільному та веде до послуг, готових рішень, можливостей автоматизації, процесу, інформації про фірму й контакту; маршрут підтверджених проєктів лишається поза навігацією до появи першого кейсу.
- [ ] Структура пояснює сценарії автоматизації через зрозумілі потреби клієнта та конкретні можливості, а не через абстрактний перелік технологій.
- [ ] Дизайн-система передає maximalist luxury характер через багатошарову композицію, глибину, світло, WebGL/3D-enhancement і виразний motion, зберігаючи послідовну типографіку, достатній контраст, читабельну ієрархію та повну функціональність без WebGL.
- [ ] Референс AI Home Control Platform впливає на ясність навігації та спосіб пояснення автоматизації, але не копіюється як код, назва, брендинг або чужі assets.
- [ ] Кожен заклик до дії веде до доступного способу звернення; до появи реальних контактів використовується нейтральний стан без фіктивних телефону, адреси чи пошти.
- [ ] Українська є основною мовою всіх видимих текстів, метаданих і доступних назв; архітектура не блокує додавання інших мов пізніше.

### Accessibility, quality and content integrity

- [ ] Семантика сторінок, headings, landmarks, focus states, alt text та labels підтримують доступне користування без миші.
- [ ] Макет є fluid у діапазоні 375–1980+ px і перевіряється у Chromium на ширинах 375, 768, 1024, 1440 та 1980 px без горизонтального скролу, обрізаного контенту, fixed-width залежностей або недосяжних контролів.
- [ ] Інтерактивні елементи мають видимі hover/focus/active стани та не залежать лише від кольору.
- [ ] Оптимізовано завантаження: зображення мають доречні розміри й розміри макета, а декоративні ефекти не блокують читання чи взаємодію.
- [ ] Ліцензовані та згенеровані візуалізації без людей дозволені для «Готових рішень» без видимої AI-позначки; вони представляють готові до реалізації конфігурації та проходять перевірку provenance, прав використання, фізичної правдоподібності й відсутності AI-артефактів.
- [ ] Твердження про фактично виконаний кейс, клієнта, адресу, дату, площу, бюджет або результат публікується лише після отримання відповідних матеріалів.
- [ ] Перед PR є доказ збірки та перевірки зміненого UI; візуальні зміни супроводжуються viewport-скриншотами або рівноцінним відтворюваним доказом.

### Delivery governance

- [ ] Є короткий `AGENTS.md`, що направляє до tracker, domain docs та workflow без дублювання довідкового змісту.
- [ ] Є один `CONTEXT.md` із доменною мовою без implementation details, а ADR створено лише для важко зворотних рішень.
- [ ] GitHub Issues є єдиним робочим tracker; доступні labels `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.
- [ ] Після bootstrap кожна зміна має Issue, окрему гілку й PR; force-push не використовується.
- [ ] Кожен PR містить посилання на Issue, acceptance criteria, докази перевірки та проходить незалежний review до merge.
- [ ] Issue та PR templates збирають відтворюваний контекст українською й не заохочують до публікації секретів.
- [ ] `CONTRIBUTING.md` і `SECURITY.md` пояснюють внесок, повідомлення вразливостей та межі відповідальної комунікації.

### Agent workflow

- [ ] У `.codex/config.toml` Sol/xhigh є root default, multi-agent режим увімкнено, а одночасно доступно не більш як чотири дочірні агенти.
- [ ] Project-local roles використовують Terra для суттєвих задач і Luna для механічного verifier; write roles мають обмежені інструкції, review roles — read-only sandbox.
- [ ] Документовано handoff: Issue/PR, критерії, scope файлів, команда валідації, результат і ризики.
- [ ] Усі 14 встановлених Matt Pocock skills мають конкретне місце в workflow.

## Out of scope

- Реальні контакти, ціни, юридичні умови, підтверджені кейси, сертифікати, відгуки та інтеграції розумного будинку без матеріалів від власника.
- Серверна логіка, CRM, форми з обробкою персональних даних або аналітика, що потребує зовнішніх ключів чи політики приватності.

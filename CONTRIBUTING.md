# Contributing

Дякуємо за внесок у Smart Electrics. Комунікація, Issue, PR та видимий контент ведуться українською.

## Перед початком

1. Прочитайте `AGENTS.md`, `CONTEXT.md` і релевантні ADR.
2. Створіть або оберіть GitHub Issue. Після bootstrap не починайте зміну без Issue.
3. Створіть гілку від актуальної базової гілки з номером Issue, наприклад `123-hero-navigation`.
4. Обмежте зміну критеріями Issue; не змінюйте чужі незакріплені файли.

## Pull request

- Вкажіть `Closes #<номер>` або інше посилання на Issue.
- Опишіть результат для користувача, виконані acceptance criteria й команди перевірки з фактичним результатом.
- Для UI додайте відтворюваний візуальний доказ на потрібних viewport.
- Не додавайте секрети, персональні дані чи непідтверджені комерційні твердження.
- Не виконуйте force-push. Після рев'ю виправляйте зауваження новими комітами.
- До merge потрібен незалежний review від учасника, який не є автором реалізації.

## Зміни домену й процесу

Нові доменні поняття вносьте в `CONTEXT.md` через `domain-modeling`. ADR потрібен лише для важко зворотного, неочевидного рішення з реальними альтернативами. Про зміни workflow або agent instructions повідомляйте окремо в PR.
